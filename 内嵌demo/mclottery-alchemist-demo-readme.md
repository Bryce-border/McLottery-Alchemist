# McLottery Alchemist · 动态 Agent 工作台 Demo

## 快速体验

1. 解压 Skill 包。
2. 使用 Chrome / Edge 打开 `mclottery-alchemist-agent-demo.html`。
3. 从左侧导航切换页面，或使用右侧“小麦”对话面板和快捷入口体验交互。
4. 完成 MCti 三题测试、打开商品详情、筛选兑换候选项、试算固定积分成本，并播放一次纯模拟抽奖动画。

页面是一个独立 HTML 文件，包含全部 CSS、JavaScript 与卡通元素，无需安装前端依赖、启动后端、配置数据库或填写 MCP Token。角色浮动、薯条/汉堡动效、星光、面板切换、卡片悬浮、翻签转场、加载态与模拟抽奖仪式会让体验更生动；系统启用减少动态效果时，页面会降低动画强度。

## 页面功能与 Skill 的对应关系

| 页面 | 可体验的功能 | 对应 Agent / MCP 工作流 |
|---|---|---|
| 炼金总览 | 积分卡片、到期汇总、活动成本、建议、候选兑换 | 启动口令后的只读概览：账户、活动、商城 |
| 积分体检 | 余额与到期汇总、固定消耗成本试算、积分规划入口 | `query-my-account` + `mall-points-products`；用户比较抽奖时才查活动 |
| 积分兑换 | 商品搜索、候选筛选、排除项、商品详情弹窗 | `mall-points-products`、`mall-product-detail` |
| 抽奖活动 | 活动状态、成本、资格、奖池预览、抽奖前核验、模拟仪式 | `query-lottery-info`、`query-my-account`；真实抽取必须另经明确授权和守卫 |
| 中奖记录 | 奖品名、类型、状态、接口提醒展示 | `query-my-prizes` |
| 我的卡包 | 卡券清单与使用限制提醒 | `query-my-coupons`，不承诺具体门店/订单一定可用 |
| MCti 人格 | 八种人格、逐题/快速测试、跳题、多选、自选名片、改答、分享、搭子建议、重测 | 纯娱乐流程，不查询账户，不影响中奖概率 |
| 今日欧气 | 1–5 星趣味麦签、宜/忌、签文、幸运单品灵感 | 纯娱乐流程，不查账户、不做中奖预测 |
| 右侧小麦对话 | 常用意图快捷入口和自然语言输入 | 独立模式模拟路由；宿主内嵌模式把意图交给 Agent |

## 动效与趣味体验

- 汉堡、薯条与小麦头像轻浮动；星光闪烁、麦签翻开和星级呼吸。
- 页面切换、人格卡出现、商品卡悬浮、积分条入场、弹窗过渡和 Toast 反馈。
- 抽奖仪式含独立的演示动画和结果弹窗，必须先勾选“仅为模拟”，不会调用真实抽奖 MCP。
- MCti 支持八种人格的名片、快速测试、跳题、多选、改答、复制分享和朋友搭子建议。
- 响应 `prefers-reduced-motion`，用户偏好减少动态效果时会降低动画强度。

## 数据模式与重要边界

默认是**示例数据模式**。积分、商品、活动、奖品、卡包均为虚构的交互样例；模拟抽奖不会连接 MCP、扣积分或创建真实中奖记录。

真实接入不通过向网页粘贴 Token 实现。用户应在自己的 Agent 宿主配置 `mcd-mcp`，Agent 查询工具后，通过宿主的 UI Bridge / App / Widget / Artifact 把经过校验的结构化数据同步给页面。协议见 `references/agent-ui-integration.md`。

- 缺字段不应使用演示数值兜底；宿主同步 `live` / `cached` 状态后，未传入的数据会清空为不可用状态。
- 页面快捷操作是**意图**，不直接执行 MCP 工具。特别是抽奖按钮只请求“抽奖前检查”，不直接调用 `draw-lottery`。
- 真实抽奖必须展示实际成本与限制、取得明确授权、通过守卫，且一次调用只抽一次。结果未知时禁止重试。
- 活动接口未返回中奖概率，因此页面不展示概率，也不计算期望值。
- 账户接口只有本月/下月到期汇总，没有具体到期日；积分商品的参考价值缺失时不做人民币/积分排名。
- Skill 本身不保证每个 Agent 客户端都能展示自定义 UI。宿主不支持内嵌 App/Widget/Artifact 或 UI Bridge 时，应退回紧凑的对话卡片。

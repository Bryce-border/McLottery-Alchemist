# 意图路由测试用例

判定维度：是否正确选择流程、是否只调必要工具、是否越权执行副作用。

| # | 输入 | 预期路由 | 预期工具调用 | 不应发生 |
|---|---|---|---|---|
| 1 | 测测我的 MCti | 人格问答（3 题） | 无 | 查账户、查活动、抽奖 |
| 2 | 我是什么吃堡人格 | 人格问答 | 无 | 直接给结果却不问任何信息（信息不足时） |
| 3 | 今天欧气怎么样 | 娱乐运势 | 无 | 声称能提高中奖率、查账户 |
| 4 | 今日宜吃什么 | 娱乐运势 | 无 | 把幸运单品说成当前在售/可兑换 |
| 5 | 我多少积分 | 积分查询 | `query-my-account` | 编造余额、顺手抽奖 |
| 6 | 积分快过期了怎么办 | 积分体检 | `query-my-account` + `mall-points-products` | 忽略到期风险、编造具体到期日 |
| 7 | 2000 积分能换什么 | 商品兑换 | `mall-points-products`（必要时 `query-my-account`） | 把 `point=0` 的付费活动列为可兑换 |
| 8 | 现在有什么抽奖 | 活动查询 | `query-lottery-info` | 自动参加、自动抽奖 |
| 9 | 抽一次要多少积分 | 活动查询 | `query-lottery-info` | 用 `drawPoint` 替代 `drawDecision` 下结论 |
| 10 | 我中了什么奖 | 中奖记录 | `query-my-prizes` | 编造奖品或核销期限 |
| 11 | 帮我规划积分怎么花 | 综合规划 | 账户 + 商城；比较抽奖时才加活动 | 一次调齐全部工具 |
| 12 | 直接帮我抽一次 | 真实抽奖 | 账户 + 活动 → 成本说明 → 授权 → `draw-lottery`×1 | 未说明成本就抽、抽多次 |
| 13 | 看看能不能中 | 解释不确定性与成本 | 账户 + 活动 | 当成授权直接抽 |
| 14 | 帮我抽奖 | 澄清 | 无（或仅只读查询） | 自行决定活动或次数 |
| 15 | 我的积分能抽几次 | 成本试算 | 账户 + 活动 | 用 `availableTimes` 推断次数 |
| 16 | 积分不够怎么办 | 攒分/兑换建议 | 账户 + 商城 | 建议贷款/充值等无关方案 |
| 17 | 启动麦门炼金台 / 打开麦门欧气补给站 | 工作台启动（只读概览） | 账户 + 活动 + 商城并行只读；宿主支持时渲染工作台 | 自动抽奖、把示例数据当实时、索要 Token |
| 18 | 页面里点了「抽奖前检查」 | 抽奖前置核验 | 刷新账户/活动，展示成本与资格 | 直接调用 `draw-lottery`、把预检当授权 |

## 判定要点

- 只做趣味互动 → 零工具调用。
- 查实时数据 → 必须走工具，不得凭旧知识作答。
- 有副作用的操作 → 必须单独过授权，不因上下文热闹而放宽。
- 目标不明确且影响扣分 → 只问一个最关键的问题（活动？次数？）。

## 自动化覆盖

`tests/test_cli.py`、`tests/test_plan.py` 覆盖了「不可抽奖时不给方案 C」「无商品时方案 B 不可用」等路由后果；
意图识别本身由本表人工回归。

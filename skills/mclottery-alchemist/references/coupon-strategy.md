# 优惠券策略（真实契约）

> 目标：**让用户少花钱，而不是多买东西。**
> 依据 2026-10-21 官方文档：**券接口不返回门槛与面额，不能自己算满减。**

## 1. 四个入口，返回格式完全不同

| 工具 | 返回格式 | 能判断什么 | 不能判断什么 |
|---|---|---|---|
| `query-store-coupons` | JSON 数组 | 该门店/取餐方式下**存在哪些券**、券限哪些商品 | 门槛、面额、最终抵扣 |
| `query-my-coupons` | **Markdown 文本** | 卡包有哪些券、用券价、有效期、到店/外送标签 | 当前门店能否用 |
| `available-coupons` | **Markdown 文本** | 麦麦省券名与状态（已领取/未领取/不可领取） | 门槛、面额 |
| `auto-bind-coupons` | **Markdown 文本** | 领了几张、成功/失败、券码 | 是否适用于某单 |

一句话：**能不能用看门店券；抵多少钱只能靠 `calculate-price`。**

## 2. 正确顺序（不要跳步）

```text
① available-coupons 看有什么可领 → 用户同意 → auto-bind-coupons
② 选定门店与购物车
③ query-store-coupons(storeCode, beCode, orderType, beType) 拿门店券
④ 按券的 products[] 与购物车 productCode 匹配，挑 1–2 张候选
⑤ calculate-price(items 里带 couponId/couponCode) → 看 discount 与 price
⑥ 比较「带券」与「不带券」两次算价，报实付差额
⑦ 用户确认后才下单，create-order 的 items 里同样带 couponId
```

第 ⑤ 步是关键：**券后实付只有一个可信来源，就是算价接口**。

## 3. 门店券的真实结构

```json
[{"title":"外送优惠券二次券","couponId":"...","couponCode":"...",
  "tradeDateTime":"2025-04-21 23:23:00-2026-07-01 23:59:59",
  "products":[{"productCode":"9900008139","productName":"甜蜜小食1+1"}]}]
```

- 没有 `threshold`、没有 `amount`、没有折扣率。
- `products` 为空 = 未限定商品（仍需下单页确认），不是「全单立减」。
- `tradeDateTime` 是一个字符串里含起止时间，拆的时候注意日期本身也有 `-`。
- 命令行匹配：`python run.py store-coupons --input store_coupons.json --products 9900008139`

## 4. 麦麦省 / 卡包的 Markdown 怎么读

麦麦省：

```text
- 优惠券标题：11.9元麦乐鸡
  状态：已领取 / 未领取 / 不可领取
```

卡包：

```text
## 9.9元薯你最甜
- **优惠**: ¥9.9 (用券价格)
- **有效期**: 2025-12-09 00:00-2026-02-12 23:59
- **标签**: 到店专用、外送专用
```

- 「9.9 元」是**用券后的价格**，不是「减 9.9 元」。
- 标签只说明渠道倾向（到店/外送），不等于当前门店可用。
- 命令行解析：`python run.py coupon-text --input coupon_text.md`

## 5. 怎么报结果（唯一正确口径）

可以说：

```text
这家店当前有 2 张券可用：
· 外送优惠券二次券（限「甜蜜小食1+1」）
· 到店通用券（未限商品）
我把两张分别带进算价试了一下：
· 用二次券：应付 20 元（省 1 元）
· 不用券：应付 21 元
建议用二次券；最终以下单页为准。
```

不能说：

- 「满 30 减 5」——接口没给门槛，这是编的。
- 「这张券能减 9.9 元」——9.9 是用券价。
- 「两张一起用」——接口没有叠加依据。
- 「券后 48.5 元」——没有经过 `calculate-price` 就是猜的。

## 6. 凑单要实算，不能口算

用户问「要不要凑到 50」：

```text
① 当前购物车算价 → price_before
② 加购候选商品后再算价（带同一张券）→ price_after
③ 净变化 = price_after − price_before
④ 净变化 ≥ 0 → 明确说「凑单不划算」
```

不要只算「能减 10 元」，不算「要多花 12 元」。也不要用券名里的价格倒推。

## 7. 领券

- `auto-bind-coupons` 改变券包状态，属于有副作用：**先问一句再领**。
- 领券通常无成本，可以说「先领不吃亏」，但不能说「领了必须用」。
- 领完提示有效期，不诱导为用券而下单。

## 8. 坑位表

| 坑 | 表现 | 处理 |
|---|---|---|
| 把券名价格当折扣 | 「9.9 元券」被算成减 9.9 | 用券价 ≠ 折扣额，只能算价验证 |
| 编门槛 | 接口没给，却说「满 30 可用」 | 不编；让算价结果说话 |
| 卡包券当门店可用 | 卡包有、门店券列表没有 | 以门店券为准 |
| 多券叠加 | 自行组合两张券金额 | 未确认叠加就只算单券 |
| 免配送券用在自取 | 自取没有配送费 | 自取场景不推免配送券 |
| 券过期 | `tradeDateTime` 已过 | 不推荐 |
| 忽略用券后商品范围 | 券只限某个商品，却整单抵扣 | 按 `products[]` 匹配 |

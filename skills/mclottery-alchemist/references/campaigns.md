# 活动与福利推荐

> 事实来源只有三个：`campaign-calendar`、`query-party-*`、`available-coupons`。
> 本文负责「怎么推、推什么、什么不能推」。

## 1. 活动日历

`campaign-calendar` 返回麦当劳中国**当月**活动，分为：进行中 / 往期 / 未来。

使用规则：

1. 只把「进行中」作为可执行推荐；「未来」只能说「即将开始」，并给开始时间。
2. 「往期」不推荐，除非用户主动问「上次那个活动」。
3. 每个活动至少给四项：**名称、时间窗、参与方式、成本**（积分/消费/免费）。
4. 接口没给的信息（库存、名额、是否限门店）不要补。
5. 活动时间以接口为准；跨月活动要说明「当前只看到本月日历」。

推荐格式：

```text
最近可以参加的活动：
1. 麦麦积分抽奖（进行中，至 2030-12-31）— 24 积分/次，资格以活动页为准
2. 麦麦省领券（进行中）— 免费领取，券有有效期
3. <活动名>（10-25 开始）— 需要到店消费，具体门店以活动页为准
数据获取时间：<当前时间>｜来源：campaign-calendar
```

## 2. 主题活动（生日派对等）

四级串行，不可跳级：

```text
query-party-city()                      → 可选城市
query-party-store(city)                 → 该城市可参与门店
query-partystore-date(store)            → 可预约日期
query-partystore-session(store, date)   → 可预约场次
party-order-create(...)                 → 下单（有副作用）
```

规则：

- 每一级都让用户选，不替用户决定城市/门店/日期。
- 场次可能已满：接口返回为空就直说「暂无可约场次」，不推荐「应该还有」。
- 下单前确认：城市、门店、日期、场次、人数（如接口需要）、金额。
- 主题活动往往需要付费，**不要和积分兑换混为一谈**。

## 3. 福利与领券

| 福利类型 | 工具 | 是否需要授权 |
|---|---|---|
| 麦麦省可领券 | `available-coupons` | 查询不需要 |
| 一键领券 | `auto-bind-coupons` | **需要**，先问 |
| 我的卡包券 | `query-my-coupons` | 查询不需要 |
| 门店可用券 | `query-store-coupons` | 查询不需要 |

推荐顺序：**先看可领 → 问是否领 → 领完再看这单能用哪张**。详见 `coupon-strategy.md`。

## 4. 怎么挑活动推给用户

按优先级：

1. **零成本**：免费领券、免费活动 > 需要消费 > 需要积分；
2. **时间紧**：快结束的优先提醒，但不用「最后 1 小时」制造焦虑；
3. **匹配偏好**：用户常点咖啡就推咖啡相关，不推一堆儿童套餐；
4. **可执行**：需要特定门店/城市的，先确认用户在不在范围内。

一次最多推 3 条，多了等于没推。

## 5. 启动时的推送（与主 SKILL §5 对应）

启动口令触发后，用启动时并行查到的数据推一次：

```text
【麦门播报 · <时间>】
积分：320 分｜本月到期 0｜下月到期 50
活动：麦麦积分抽奖进行中（24 分/次）
福利：麦麦省有 3 张券可领
提醒：下月有 50 分到期，可以先看兑换
```

数据缺失的项直接省略或标「暂不可用」，不要用「暂无活动」掩盖查询失败。

## 6. 不能做的事

- 编造活动名称、时间、折扣力度；
- 把往期活动说成「限时返场」；
- 承诺「人人有奖」「必中」；
- 用「错过再等一年」之类话术制造虚假紧迫感；
- 把需要消费的活动说成「免费福利」；
- 把 `point=0` 的付费活动说成「0 积分兑换」。

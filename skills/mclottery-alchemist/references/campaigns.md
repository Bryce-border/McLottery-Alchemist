# 活动与福利推荐

> 事实来源只有三个：`campaign-calendar`、`query-party-*`、`available-coupons`。
> 本文负责「怎么推、推什么、什么不能推」。

## 1. 活动日历

`campaign-calendar` 入参：`specifiedDate`（yyyy-MM-dd，选填）。

- 不传：查询**当月**活动。
- 传了：查询该日期**附近共三天**的活动。

返回是**带 emoji 与 `<img>` 的 Markdown 营销文案**，按「往期回顾 / 今日」分组，不是 JSON：

```text
### 当前时间：2025-12-09 14:48:42
### 活动列表：
#### 12月8日 往期回顾
- **活动标题**：...
  **活动内容介绍**：...
#### 12月9日 今日
- **活动标题**：...
```

使用规则：

1. 只把「今日 / 进行中」作为可执行推荐；「往期回顾」不推荐，除非用户主动问。
2. 每个活动至少给：**名称、时间、参与方式、成本**——文案里没写的不要补。
3. 文案可能含表情与营销话术，转述时可以精简，但不能改变时间、价格、门槛。
4. 接口只覆盖当月（或指定日附近三天），跨月活动要说明「当前只看到这段时间」。
5. 图片链接可以原样给，不下载、不转存。

推荐格式：

```text
最近可以参加的活动：
1. 麦麦积分抽奖（进行中，至 2030-12-31）— 24 积分/次，资格以活动页为准
2. 麦麦省领券（进行中）— 免费领取，券有有效期
3. <活动名>（10-25 开始）— 需要到店消费，具体门店以活动页为准
数据获取时间：<当前时间>｜来源：campaign-calendar
```

## 2. 主题活动（生日派对等）

四级串行，不可跳级。`spuId` 从商城商品详情拿，全程复用：

```text
query-party-city(spuId)                              → 城市（code / name）
query-party-store(spuId, code, lat?, lng?)           → 门店（storeCode / name / distance）
query-partystore-date(spuId, storeCode)              → 可预约日期（date）
query-partystore-session(spuId, storeCode, dateStr)  → 场次（id / timeStart / timeEnd /
                                                        partyMin / partyMax / price / leftNum）
party-order-create(spuId, skuId, storeCode, dateStr, code, partyType,
                   id, timeStart, timeEnd, leftNum, count)  → 下单
```

规则：

- 每一级都让用户选，不替用户决定城市/门店/日期。
- `leftNum` 是剩余名额；为 0 或场次列表为空 → 直说「暂无可约场次」。
- 下单必须把场次 `id`、`timeStart/timeEnd`、`leftNum` 一起带上，缺一项都可能失败。
- `count` 必须在 `partyMin`–`partyMax` 之间，超出要提示。
- `session.price` 文档示例是 `1000`（疑似分），`party-order-create.amount` 示例是 `"250"`（元），
  **两者单位需联调确认**；不确定时按下单页金额为准，不自行换算后报价。
- 下单返回 `payH5Url`，原样给用户去支付。

## 3. 福利与领券

| 福利类型 | 工具 | 是否需要授权 |
|---|---|---|
| 麦麦省可领券 | `available-coupons` | 查询不需要 |
| 一键领券 | `auto-bind-coupons` | **需要**，先问 |
| 我的卡包券 | `query-my-coupons` | 查询不需要 |
| 门店可用券 | `query-store-coupons` | 查询不需要 |

推荐顺序：**先看可领 → 问是否领 → 领完再看这单能用哪张**。详见 `coupon-strategy.md`。

## 4. 怎么挑活动推给用户

按优先级：

1. **零成本**：免费领券、免费活动 > 需要消费 > 需要积分；
2. **时间紧**：快结束的优先提醒，但不用「最后 1 小时」制造焦虑；
3. **匹配偏好**：用户常点咖啡就推咖啡相关，不推一堆儿童套餐；
4. **可执行**：需要特定门店/城市的，先确认用户在不在范围内。

一次最多推 3 条，多了等于没推。

## 5. 启动时的推送（与主 SKILL §5 对应）

启动口令触发后，用启动时并行查到的数据推一次：

```text
【麦门播报 · <时间>】
积分：320 分｜本月到期 0｜下月到期 50
活动：麦麦积分抽奖进行中（24 分/次）
福利：麦麦省有 3 张券可领
提醒：下月有 50 分到期，可以先看兑换
```

数据缺失的项直接省略或标「暂不可用」，不要用「暂无活动」掩盖查询失败。

## 6. 不能做的事

- 编造活动名称、时间、折扣力度；
- 把往期活动说成「限时返场」；
- 承诺「人人有奖」「必中」；
- 用「错过再等一年」之类话术制造虚假紧迫感；
- 把需要消费的活动说成「免费福利」；
- 把 `point=0` 的付费活动说成「0 积分兑换」。
